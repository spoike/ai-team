# UX Standards

## Purpose

Create experiences that are intuitive, efficient, and accessible.

Users should be able to accomplish their goals with minimal effort and confusion.

## Core Principles

### User-Centered Design

Design for user goals, not system structure.

Users should not need to understand implementation details to complete tasks.

Focus on:

- User needs
- User expectations
- User outcomes

### Consistency

Similar actions should behave similarly.

Consistent:

- Terminology
- Navigation
- Visual patterns
- Interaction patterns

Reduces cognitive load and learning effort.

### Clarity

Interfaces should communicate intent clearly.

Avoid:

- Ambiguous terminology
- Hidden functionality
- Unexpected behavior

Users should understand:

- What happened
- What is happening
- What happens next

### Simplicity

Prefer the simplest experience that satisfies requirements.

Reduce:

- Unnecessary decisions
- Excessive configuration
- Information overload

Every additional option adds complexity.

### Feedback

The system should always communicate its state.

Provide feedback for:

- User actions
- Loading states
- Success states
- Error states
- Background operations

Users should never wonder whether something happened.

## Forms

Forms should:

- Minimize required input
- Validate as early as practical
- Provide clear error messages
- Preserve entered data when possible

Error messages should explain:

- What is wrong
- Why it is wrong
- How to fix it

## Navigation

Users should:

- Know where they are
- Know where they can go
- Know how to return

Avoid deep or confusing navigation structures.

## Error Handling

Errors should be:

- Actionable
- Understandable
- Non-technical

Avoid displaying raw system messages to end users.

Provide:

- Clear explanation
- Recovery guidance
- Next steps

## Empty States

Empty states should be intentional.

Explain:

- Why no data exists
- What the user can do next

Avoid blank screens.

## Performance Perception

UX includes perceived performance.

Consider:

- Loading indicators
- Progressive loading
- Skeleton screens
- Optimistic updates

Users tolerate waiting better when informed.

## Accessibility

Accessibility is part of user experience.

All UX recommendations must comply with:

- accessibility.md

Accessibility concerns override aesthetic preferences.

## Mobile Experience

Consider:

- Touch interaction
- Screen size
- Orientation changes
- Reduced precision input

Features should remain usable on smaller screens when applicable.

## UX Review Checklist

Before approving a design, consider:

- Is the user's goal clear?
- Is the workflow intuitive?
- Is terminology understandable?
- Is navigation obvious?
- Are errors recoverable?
- Are edge cases handled?
- Is accessibility considered?
- Is the experience consistent?
- Is the solution simpler than alternatives?

## Guiding Question

When evaluating alternatives:

Choose the solution that minimizes user effort while maximizing user confidence.
